1 · a analogia central

Cada texto é uma casa num mapa de significados

O embedding é o endereço numérico. Textos do mesmo assunto moram no mesmo bairro — mesmo sem compartilhar palavras. Clique nos botões e passe o mouse nos pontos.

🎯 O que observar

Com a query “amo sopa”, os vizinhos quentes são paráfrases (“sopa é minha favorita”). Com “mudança climática”, o vizinho quente é “aquecimento global” — zero palavra em comum, sentido igual. É isso que busca por keyword nunca acharia.

⚠️ E o código de erro?

“ERR_TIMEOUT_CDP v2.4.1” cai longe de tudo, no bairro errado. Vetor denso dilui termo raro/exato — por isso existe busca híbrida (tela 10). Guarde essa intuição.

2 · o que é um embedding, de verdade

Uma lista de números. Nada mais — e nada menos.

“Obscura é uma engine de browser” → [-0.012, 0.044, -0.31, …, 0.007] 1536 números

regra 1

🗺️ Modelo diferente = mapa diferente

Vetores OpenAI não são comparáveis com BGE ou E5. Escolheu o modelo: use o mesmo para indexar e consultar. Trocar de modelo = reindexar tudo.

regra 2

🪟 Janela de entrada limitada

Cada modelo aceita no máximo N tokens (3-small: 8192 · Voyage-4: 32000). Texto maior é truncado — ou fatiado com chunking (tela 4).

regra 3

🧪 Significado distribuído

Nenhuma posição isolada “significa” algo. E marque input_type quando o modelo distingue query vs documento (Cohere, Voyage).

Exemplo mínimo — gerar um embedding (Python, API OpenAI)

# referência: developers.openai.com → guides → embeddings
from openai import OpenAI
client = OpenAI()
resp = client.embeddings.create(
    input="Obscura é uma engine de browser para agentes",
    model="text-embedding-3-small")
vetor = resp.data[0].embedding  # lista de 1536 floats

Atalho que economiza horas: com vetores de norma L2 = 1, cosine, dot e L2 ordenam igual. Não gaste energia na métrica no início — gaste em bons chunks e top-K. APIs como a Jina expõem flag normalized: true.
# busca mínima, sem servidor — só NumPy
import numpy as np
def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return float(np.dot(a,b)/(np.linalg.norm(a)*np.linalg.norm(b)))

4 · por que fatiar textos

Um manual de 50 páginas vira sopa sem graça num vetor só

Vetor de texto longo = ponto médio diluído no mapa. Por isso fatiamos em chunks de 1 ideia, com overlap. Teste abaixo:

✅ Regras de bolso

① Respeite fronteiras naturais (parágrafo, heading, nunca no meio da frase) · ② 200–800 tokens com 10–20% de overlap · ③ 1 chunk = 1 ideia · ④ guarde metadados: URL, fetched_at, título, posição.

🚫 Anti-padrões

Página inteira = 1 vetor · corte de tamanho fixo no meio da palavra · jogar fora a URL após vetorizar (o “grounded” do RAG morre aqui — sem fonte, sem citação).

🎛️ Simulador do funil — 40 evidências, qual entra na síntese?

“Lost in the middle”: 40 trechos no prompt estouram contexto e o LLM se distrai com trecho fraco. 6–8 trechos fortes + URL de cada um = síntese melhor e mais barata. Se nenhum trecho presta, a resposta correta é “não encontrei nas fontes” — não inventar.

10 · além do vetor denso

Vetor erra termo exato. A cura é combinar sinais.

Mova o α (alpha): α=1 é só vetor, α=0 é só keyword (Weaviate). Observe qual query cada extremo acerta.

📇 BM25 — o keyword clássico imbatível no exato

Conta frequência do termo com saturação + normaliza por tamanho do doc. Para ERR_TIMEOUT_CDP, SKU, versão v2.4.1: embedding dilui, BM25 acerta em cheio.

🌵 Sparse / SPLADE — “BM25 aprendido”

Vetor gigante e quase todo zero, com peso por termo do vocabulário. Qdrant e Chroma guardam sparse ao lado do denso; o BGE-M3 gera os dois juntos numa passada só.

🎖️ Rerankers — o maior salto qualidade/custo

Cross-encoder lê (query, documento) juntos e dá nota fina. Padrão: retrieve 30–100 → rerank top 5–10. Opções: Cohere Rerank (multilíngue, 4096 tokens) ou bge-reranker open-source local.

11 · quando vetor não basta

Perguntas multi-hop pedem grafo, não top-K

“Quais ferramentas citadas pelas Evidências X e Y compartilham o mesmo mantenedor?” — nenhum chunk isolado contém a resposta. Clique nos nós para explorar.

🖱️ Clique num nó

Cada clique mostra entidade, tipo e relações — o que o GraphRAG extrai com LLM antes de responder.

🔧 Pipeline GraphRAG (Microsoft, open-source)

① extrair entidades + relações do texto com LLM → ② detectar comunidades → ③ responder perguntas globais atravessando o grafo. Refs: github.com/microsoft/graphrag, paper arxiv 2404.16130.

Avisos honestos: o próprio README diz que é projeto de pesquisa, hoje em modo manutenção, e a indexação é cara (muitas chamadas LLM para extrair o grafo). Para pesquisas web pontuais, as sub-buscas do loop multi-turno já cobrem — GraphRAG fica estacionado (ver tela 14).

12 · o outro uso de embeddings

LLM esquece tudo entre chamadas. Memória = passado relevante no prompt.

Aperte rodar turno e veja o loop: embed → recall → decidir → responder → escrever de volta.

turno 0
🔢embed(pergunta)
🎯recall top-K + thread
🧠LLM decide
✍️responde + salva

Cada turno enxerga o que o anterior aprendeu.

curto prazo

💬 Thread atual

Últimos N turnos no prompt. LangChain/LangGraph: checkpointer por thread.

longo prazo

🗄️ Store entre sessões

JSON + busca vetorial por namespace. LangGraph: store + IndexConfig(embed=…). Letta/MemGPT: agentes stateful com recall vetorial.

padrões

🧩 Cache · episódica · agentica

Cache semântico: pergunta parecida → reusa resposta. Episódica (“na Sessão 12…”) vs semântica (“Obscura usa CDP”). Agentic RAG: o agente decide quando buscar.

3 regras que separam memória boa de pântano: ① indexe sínteses, não dumps — vetor de texto sujo recupera sujeira · ② esqueça com TTL/consolidação (LangGraph filtra por namespace) · ③ filtro antes do vetor: metadados (mesma Pesquisa? data válida?) e só então similaridade.

13 · exemplos inteligentes em agentes

5 cenários — clique para abrir cada história

“já vimos isso”

Cenário 1 — Dedup semântica de Evidências

Problema: mesma página com URL diferente (?utm=…, http vs https) ou republicação — dedup por URL falha. Solução: embedding por Evidência; similaridade > 0.93 → marca duplicada, não re-sintetiza. Armadilha: threshold alto junta coisas distintas — registre (url_a, url_b, score) para auditar.

“menos é mais”

Cenário 2 — Rerank antes da síntese

Problema: 40 Evidências estouram o prompt (“lost in the middle”). Solução: retrieve 40 → rerank top 6–8 → só esses na síntese, cada um com URL. Custo: 1 chamada de rerank por Turno final — barato perto de re-sintetizar contexto gigante.

“já respondemos isso”

Cenário 3 — Cache semântico de Pesquisas

Problema: “o que é Obscura?” → “me explica a engine Obscura” re-busca tudo. Solução: embedding do objetivo + síntese; similaridade > 0.9 e fontes frescas → reusa (marcando reuso). Armadilha: web envelhece — combine com fetched_at, senão vira resposta velha confiante.

“continuar de onde parei”

Cenário 4 — Memória de Sessão em 2 camadas

a) resumo rolante: ao fechar cada Turno, 3–5 linhas (achado, decisão, pendência). b) recall vetorial sobre resumos + Evidências: o Turno 16 pergunta “o que sabemos sobre preço?” sem reler 15 Turnos. Receita MemGPT/Letta + LangGraph store, adaptada para arquivo.

bônus avançado

Cenário 5 — Juiz de relevância

Passo “juiz” pontua cada Evidência contra o objetivo (0–2: irrelevante/parcial/central) e decide: sintetizar, buscar mais ou reformular a query. Embeddings pré-ordenam antes do juiz LLM, barateando o passo. Só quando o loop já funciona — otimização, não fundação.

14 · só para este repo

Web-search via Obscura: o que fazer primeiro

CLI file-based, sem DB (ADR-0002), vocabulário Pesquisa → Sessão → Turno → Evidência. Filtre a matriz por veredito:

#IdeiaEsforçoValorVeredito

🗺️ Recomendação faseada

Fase 0 — esta semana, sem ML. Dedup URL+hash + corte top-N determinístico + registrar score e motivo em cada Evidência no JSONL (formato migrável para turns). Custo zero.
Fase 1 — com o harness. Reranker (API) atrás de flag; comparar com/sem rerank em 20–30 perguntas; guardar decisão.
Fase 2 — quando paráfrase doer. Embeddings só para dedup; vetores em arquivo lado a lado; threshold calibrado. Se virar gargalo → sqlite-vec (a “dor” que o ADR-0002 previu como gatilho).
Não-fases. Qdrant/pgvector/GraphRAG estacionados até métrica pedir — escrito aqui para ninguém propor “vamos botar Qdrant” sem contexto daqui a 6 meses.
